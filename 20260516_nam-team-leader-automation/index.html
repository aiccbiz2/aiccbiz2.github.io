Section 01 — As-Is

지금 무엇이 불편한가

남윤수 팀장님의 현재 업무 흐름에서 추출한 세 가지 페인포인트. 각각 다른 영역이지만 모두 "수기 추적의 한계"라는 공통 원인을 갖는다.

01
개인 일정 관리
OneNote에 텍스트 번호 리스트로 To-Do 수기 작성
일정이 밀리면 완료 여부 추적 누락. 매번 본인이 체크해야 하는 부담
02
팀원 업무 지시
구두/메시지로 지시 후 수동 팔로업
지시 후 완료 체크 누락. 진행 단계가 보이지 않아 주간 회의 전 일괄 확인 어려움
03
활동성 평가
마당 캘린더 수동 다운로드 후 통계 산출
정량 데이터 가공이 수작업. 활용도 낮음
Section 02 — To-Be

요구사항 정의

기능 요구사항 4가지와, 모든 기술 선택을 결정짓는 단 하나의 제약.

F1 · 개인

일정·할 일 통합 노티

전체 할 일과 일정·기한을 종합하여 사전 알림. 마감 임박 항목은 우선순위 자동 표시.

F2 · 팀

팀원 업무 양방향 트래킹

지시한 업무를 팀원에게 자동 할당. 진행 단계(미시작 / 진행 중 / 거의 완료) 가시화. 미완료는 양방향 리마인드.

F3 · 입력

음성 입력 채널

안드로이드 폰 또는 사내 Windows 노트북에서 음성으로 할 일과 지시를 입력 가능.

F4 · 통계

활동성 통계 자동화

마당 캘린더 데이터 자동 추출·분석. 팀원별 활동성 리포트 자동 생성.

⚠ 핵심 제약 조건

반드시 사내 망 안에서.
M365 · Teams · Copilot · 마당 캘린더 생태계와 자연스럽게 연동되어야 한다.

Section 03 — Benchmark

검증된 운영 패턴, 그대로 이식.

양준모 팀장님이 외부망에서 이미 운영 중인 위클리 To-Do 자동화. 이 모델 자체는 사내 도구로 1:1 이식 가능하다. DB만 Notion → SharePoint List로 치환하면 끝.

양
양준모 팀장 (AI사업2팀)
현재 Notion + 자체 에이전트로 운영 중
[입력]음성 녹취 → STT → 자동 텍스트화
[저장]위클리 To-Do DB (Notion) — Status: Not Started / In Progress / Done
[발화]월요일 08:00 자동 트리거 → Not Started 항목 일괄 페이지 생성
[관리]컴플라이언스 채널에 누적 → 팀원이 상태 업데이트
[체크]주간 회의 전 팀장 일괄 확인
[이력]주차별 페이지로 영구 누적

Section 05 — Roadmap

한 명에서 한 팀으로,
4단계 8주.

Quick Win부터 시작해 점진적으로 확장. 각 단계는 다음 단계의 검증 자료를 만든다.

1
Quick Win — 본인 1명 PoC
1주 · F1 일부

Copilot에게 "오늘 일정 + 할 일 + 마감 임박" 요약 요청. Graph API로 Outlook만 연동, Teams 1:1로 매일 08:00 자동 푸시. 산출물: 동작 데모 + Copilot 라이선스 가용성 확인 + 마당 API 협의 요청서.

2
To-Do 저장소 구축
2주 · F1 완성 · F3 일부

SharePoint List 또는 Planner로 To-Do DB 구성. Power Automate로 마감 D-1, D-day 자동 알림. 음성 입력은 Teams 모바일 dictation 활용.

3
팀원 트래커 확장
3주 · F2 본격 구현

팀원 자동 할당, 양방향 노티, 진행 단계 가시화. 주간 회의 전 일괄 리포트 자동 생성.

⚠ UX 주의: 감시 느낌 최소화 — 팀원 입장 메시지 톤·빈도 설계 필수
4
활동성 통계 모듈
2주 · F4 (마당 API 협의 후)

마당 캘린더 raw 데이터 정기 추출. Power BI 대시보드로 팀원별 활동성 시각화.
